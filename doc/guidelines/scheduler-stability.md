# 基建排班防振荡规范

## 目标

排班器必须优先保证状态稳定，禁止通过低心情干员的短周期回班维持瞬时产能。正常换班、急救、纠错和菲亚梅塔充能都不得绕过同一套回班安全门槛。

## 状态转换不变量

1. 只有 `SHIFT_ON` 可以把正在宿舍休息的高效干员移动到工作区。
2. `SELF_CORRECTION` 只能修复普通空位、非休息干员错位和安全的宿舍整理；不得执行任何高效干员的 `dorm -> work`。
3. 多人组回班必须覆盖全部实际休息且非 `workaholic` 的组员，回班时间取这些成员安全就绪时间的最大值。
4. 菲亚梅塔可以让无分组目标提前回班，但不得把多人组的整组 `SHIFT_ON` 提前到充能完成后立即执行。

## 心情滞回门槛

普通回班心情门槛必须使用运行时配置计算：

```text
shift_on_mood = clamp(
    lower_limit
    + (upper_limit - lower_limit) * resting_threshold
    + 2,
    lower_limit,
    upper_limit,
)
```

该门槛比普通下班阈值多 2 点心情，形成无状态滞回。不得只使用 `lower_limit + 2`，也不得把 `.65`、`.70` 等实例值写死在代码里。

安全就绪时间应由最近一次宿舍心情、对应时间戳和回满 ETA 线性估算。数据缺失、非法或无法证明已达到门槛时，必须保守等待回满 ETA；回满 ETA 也缺失时不得生成提前回班任务，并应记录告警等待重新读取。

回满 ETA 缺失时必须生成专用宿舍重读任务。该任务只能读取动态宿舍状态，不能执行排班；同一 blocked 状态重复规划时必须保留最早重读时间，扫描失败或 OCR 漏识别后也必须移除逾期旧任务并安排下一次未来重读。readiness 候选必须以动态宿舍记录为准，不能仅依赖可能被 OCR 清空的 `current_room`。

全局急救时间、其他工作组的耗尽时间、任务合并提前量和宿舍排序都只能把任务向后推，不能把 `SHIFT_ON` 提前到任一成员的安全就绪时间之前。

## 任务队列兼容要求

- 重新计算回班任务不得改变既有 `RUN_ORDER`、`SHIFT_OFF`、`FIAMMETTA` 等非刷新目标任务的对象、数量和时间。
- `RELEASE_DORM` 不得丢失或重复。
- 同一状态重复计算必须幂等；不得基于每次调用的 `now + duration` 让回班或重读时间持续后移。
- 配置模型、数据库和任务序列化格式不是首批修复范围；如需持久冷却，应作为独立变更设计和灰度。
- 数据库中的待办专精只能由 `MasterySync` 转换为调度任务；`plan_solver` 不得重复生成即时 `SKILL_UPGRADE`，避免空闲训练室形成队首紧循环。

## 立即跑单边界

- 自定义功能只保留“立即跑单”操作与 `MaaWeeklyNew` 周计划表格；后者只能编辑 MAA 周计划数据，不得介入基建任务队列或跑单时序。
- 不得恢复相邻跑单自动合并、批量推迟其他任务、可调跑单贴近策略或对应配置项。
- 立即跑单只能选择队列中最近的未来 `RUN_ORDER`，不得创建额外跑单，也不得改动非跑单任务。
- 调度器休眠时允许通过一次性事件唤醒并重新选择队首；已有任务正在执行时，立即跑单只能排到当前连续任务批次之后。
- `immediate` 标记必须随任务状态持久化，停止和重启后仍可完成该跑单；启动时必须清理陈旧唤醒事件，执行结束后也必须复位事件和 `sleeping` 状态。
- 只有标记为 `immediate` 的跑单可以跳过订单等待并强制使用无人机，普通跑单和重启恢复任务保持原有时序。
- 立即跑单必须优先于普通跑单窗口判断；即使订单倒计时超过普通窗口，也必须继续换入跑单干员并强制使用无人机，不得误走“上一单提前完成”的领取重算分支。

## 必测场景

- 其他在岗干员 30 分钟后耗尽，而休息组两小时后才达到门槛：不得截短休息组。
- 同组恢复时间不同或宿舍优先级不同：必须等待全体实际休息组员中的最晚者。
- 全红脸急救：不得生成低于安全门槛的回班。
- 单人或整组回满 ETA 全缺：不得生成 `SHIFT_ON`，只能保留一个幂等的未来宿舍重读任务。
- 宿舍重读扫描异常或 OCR 漏识别：不得留下逾期重试紧循环，也不得因 `current_room` 为空绕过门禁。
- 混合工作/休息组与普通房间错位同时存在：纠错普通错位，但不拉回宿舍组员。
- 空岗位的主班正在宿舍：不得由 `SELF_CORRECTION` 拉回。
- 无分组/有分组菲亚目标分别保持旧行为和安全门禁。
- 红松、深海及会客室历史振荡序列回放后，不得出现 90 分钟内“回班后再次下班”。
- 跑单、菲亚、宿舍释放及任务排序测试必须保持通过。
- 立即跑单在长倒计时（现场曾为 1088 秒）下必须进入换人流程，且不得调用普通跑单的领取或重算路径。

## 部署与回滚

防振荡代码与排班配置必须分批部署和观察。首批代码灰度期间保持活动 `backup_plans=[]`，不同时调整 `rest_in_full`、替补或全局阈值。出现低于门槛回班、90 分钟内反转、菲亚拉回多人组、跑单新增漏单、队列持续增长或宿舍释放回归时，只回滚本批源码，不恢复已证实冲突的旧排班或已修复的 venv。
